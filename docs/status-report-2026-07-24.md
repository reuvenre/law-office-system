- **31 בדיקות יחידה** (`lib/erp/calc.test.ts`, `lib/messaging/messaging.test.ts`):
  עיגול מע"מ, מדרגות חריגה, הצמדת יום 29–31 בחודשים קצרים, רינדור תבניות
  תזכורת ונרמול טלפון ישראלי.
- ‏CI ב-GitHub Actions מריץ lint + typecheck + **test** + build בכל push ו-PR.
- ‏Vitest שודרג ל-4 (סוגר שרשרת פגיעויות dev של vite/esbuild).

### 2. שדרוג Next.js 14 → 16 + React 19 ✅

- ‏`next` 14.2.35 → 16.2.11 ו-`react`/`react-dom` → 19: סוגר את 10
  הפגיעויות המקוריות של Next 14 (cache poisoning,‏ SSRF ב-Server Actions,
  חשיפת endpoints ועוד).
- **הגירת שינויים שוברים**:
  - ‏`params` / `searchParams` הפכו ל-Promises — עודכנו 8 עמודים + ראוט
    הורדת המסמכים (`await params`).
  - ‏ESLint 9 flat config (`eslint.config.mjs` מבוסס ה-flat configs
    הנייטיביים של `eslint-config-next`) במקום `next lint` / `.eslintrc`
    (ש-`next lint` הוסר ב-Next 16).
  - ‏`require()` בקונפיג Tailwind הוחלף ב-import.
- **ניקוי הפגיעויות הטרנזיטיביות שנותרו** (14 → 0): ‏next-auth → beta.32
  (‏@auth/core 0.41.3), override ל-postcss, override ל-sharp ≥0.35,
  override ל-esbuild ≥0.25 (שרשרת הכלים של drizzle-kit). כלי המיגרציה
  ‏(drizzle-kit) נבדק ועובד אחרי ה-overrides.

### 3. מסכי ERP / חיוב ✅

מנוע החיוב היה קיים בצד השרת ללא UI — כעת נבנתה שכבת ממשק מלאה:

- **`/billing`** — רשימת מסמכי חיוב (חשבונות עסקה/חשבוניות), עם סכום,
  סטטוס ולקוח. מסוננת לפי הרשאת התצוגה של המשתמש (`invoiceScope`).
- **`/billing/[invoiceId]`** — כרטיס חשבונית: שורות, פירוט מע"מ, יתרה,
  רשימת תשלומים, טופס **רישום תשלום**, וכפתור **ביטול** (סימון בלבד,
  ללא מחיקה — כללי מס).
- **טאב "חיובים" בכרטיס התיק** — רישום שעות (לכל בעל גישה לתיק), גלגול
  שעות שטרם חויבו לחיוב, רשימת חיובים פתוחים ויצירת **חשבון עסקה** מהם,
  וקישור למסמכי החיוב של התיק.
- **מודל הרשאות**: צפייה פתוחה לכל משתמש מחובר (בכפוף ל-scope); פעולות
  כסף (רישום תשלום, ביטול חשבונית, יצירת חשבון עסקה) מוגבלות לתפקידי
  הנהלת חשבונות/מנהל (`requireFinanceRole`) — נמנעת חזרה על תקלת הנעילה
  שתוקנה בסבב הקודם. רישום שעות מותר לכל בעל גישה לתיק.
- הרחבת `ROLES` לכל ערכי ה-enum במסד (מנהל/מזכירה/הנהלת חשבונות/מתמחה)
  כדי שטופס הוספת המשתמש והשערים החדשים יתאימו.

## נותר לשלב הבא (המלצות)

אין יותר "חובות" פתוחים מהסקירה. להמשך פיתוח מומלץ:

1. **הרחבת בדיקות** — בדיקות אינטגרציה למנוע החיוב מול DB זמני (כרגע
   מכוסה החישוב הטהור; זרימות ה-DB — `createProforma`,‏ `recordPayment` —
   נשענות על הטיפוסים והבנייה).
2. **חשבונית מס וקבלה** — כרגע הזרימה מסתיימת בחשבון עסקה (proforma)
   ותשלום. הפקת חשבונית מס/קבלה רשמית (כולל מספור והקצאת מספר מאש"ר)
   היא ההרחבה הטבעית.
3. **מסך הגדרות פיננסי** — להעביר את שיעור המע"מ (כיום קבוע `VAT_RATE=18`)
   ל-`app_settings`, כדי שלא יידרש deploy בשינוי חוק.
4. **מעקב Next** — להישאר על הערוץ היציב; לשקול שדרוגי מינור עתידיים
   כשמתפרסמים תיקוני אבטחה.
